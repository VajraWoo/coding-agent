# 实施计划

## 总体顺序

1. 实现并验证 `local-tools`：先建立本地能力和安全边界。
2. 实现并验证 `model-client`：只负责千问 HTTP 协议和响应解析。
3. 实现并验证 `agent-runtime`：连接模型与工具，形成反馈循环。
4. 增加 CLI 和可观察输出。
5. 使用真实 API 完成端到端演示，整理提交材料和答辩笔记。

## local-tools 设计

- 一个 `WorkspaceTools` 对象绑定一个已经解析的工作目录。
- 所有模型参数先进行类型和范围检查。
- 文件路径必须是相对路径；解析后的真实路径必须仍位于工作目录内。
- `run_command` 接收参数数组并以 `shell=False` 执行，避免额外 shell 解释。
- 文件、目录列表和命令输出均有大小上限。
- 失败转为 `ToolResult(is_error=True)`，供未来 Agent 循环反馈给模型。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| `../`、绝对路径或符号链接逃逸 | `Path.resolve()` 后使用 `relative_to(workspace)` 验证 |
| 命令永久不退出 | `subprocess.run(..., timeout=...)` |
| 输出过大耗尽模型上下文 | 统一截断并加入明确标记 |
| 模型生成未知工具或错误参数 | 注册表白名单和逐字段校验 |
| 网络模型使测试不稳定 | 本模块完全不调用网络；使用真实临时目录和真实子进程测试 |
